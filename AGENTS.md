# Urubots Web - Agent Guidelines

## Tech Stack

- **Framework**: Next.js 15 (App Router, React 19; `params` is a Promise: `const { lang } = await params`, `src/app/[lang]/`)
- **CMS**: Prismic (headless) via `@prismicio/client`, `@prismicio/react`, `@prismicio/next`
- **Styling**: Tailwind CSS + styled-components (mixed — Tailwind preferred for new code)
- **Language**: TypeScript (strict: false)
- **i18n**: Multi-language via `[lang]` route segment. Locales: `en-us`, `es-ar`, `pt-br`
- **Modeling**: Prismic Type Builder + Prismic CLI (`npx prismic ...`; Slice Machine is removed). Config in `prismic.config.json`. Commands need `--task-id`/`--user-intent` (run `prismic task-id` first).

## Patterns & Conventions

### Page Pattern

Every page follows this structure:

```tsx
import { createClient } from '@/prismicio';
import Layout from '@/components/Layout';
import { getLocales } from '@/lib/getLocales';
import { SliceZone } from '@prismicio/react';
import { components } from '@/slices';
import { getMenuItems } from '@/components/Utils/MenuItems';

export default async function Page({ params: { lang } }: { params: { lang: string } }) {
  const client = createClient();
  const page = await client.getByUID('typename', 'typename', { lang }).catch(() => notFound());
  const locales = await getLocales(page, client);
  const navigation = getMenuItems(lang);

  return (
    <Layout locales={locales} navigation={navigation}>
      <SliceZone slices={page.data.slices} components={components} />
    </Layout>
  );
}

export async function generateStaticParams() {
  const client = createClient();
  const pages = await client.getAllByType('typename', { lang: '*' });
  return pages.map((page) => ({ uid: page.uid, lang: page.lang }));
}
```

### Slice Pattern

Slices live in `src/slices/<SliceName>/index.tsx` and are thin wrappers:

```tsx
import { FC } from "react";
import { Content } from "@prismicio/client";
import { SliceComponentProps } from "@prismicio/react";
import { MyComponent } from "@/components/MyComponent";

export type MySliceProps = SliceComponentProps<Content.MySliceSlice>;

const MySlice: FC<MySliceProps> = ({ slice }) => {
  return (
    <section data-slice-type={slice.slice_type} data-slice-variation={slice.variation}>
      <MyComponent slice={slice} />
    </section>
  );
};

export default MySlice;
```

After creating a new slice, register it in `src/slices/index.ts`:

```tsx
my_slice: dynamic(() => import("./MySlice")),
```

### Component Pattern

Components live in `src/components/<Name>/index.tsx`. They receive slice data as props. Heavy logic stays in the component, not the slice wrapper.

### Custom Type Pattern

Custom types are JSON schemas in `customtypes/<name>/index.json`. They define the Prismic document structure. Fields go under `"Main"` tab, SEO fields under `"SEO & Metadata"`.

### Navigation

Menu items are hardcoded per locale in `src/components/Utils/MenuItems.tsx`. Each locale has an array of `Menu` objects with `{ id, title, path, newTab }`. When adding a new page, add entries for ALL locales (`en-us`, `es-ar`, `pt-br`).

### Styling

- Use Tailwind CSS utility classes for new code
- Some older components use styled-components — don't refactor unless asked
- Color palette defined in `tailwind.config.ts` (blue-50 to blue-950, white-50 to white-950)
- Dark mode supported via `class` strategy

### Path Aliases

- `@/` maps to `src/` (configured in tsconfig.json)

## Rules

- Always use `lang` parameter from route params for Prismic queries
- Always call `getMenuItems(lang)` and `getLocales(page, client)` in pages
- Always wrap page content in `<Layout locales={...} navigation={...}>`
- Use `@prismicio/react` components (`PrismicRichText`, `PrismicImage`, `PrismicLink`) for Prismic fields
- Use `createClient()` from `@/prismicio` — never instantiate Prismic client directly
- Static generation: export `generateStaticParams` in every page with `lang: '*'`
- When creating new content types, add corresponding route in `src/prismicio.ts`
- **Prismic is the single source of truth for content.** Always model content (texts, lists, links, images, publications, team members, awards, etc.) as Prismic custom types/slices and render it from Prismic data. Do NOT hardcode content in one-off components or scatter it across files (data modules, config constants, JSX strings). Components only render data received from Prismic via props.
- If new content needs new fields, extend the slice/custom type model (`src/slices/<Name>/model.json`, `customtypes/<name>/index.json`) instead of adding a local data file.
- Translatable text must live in Prismic per locale, not in inline per-locale dictionaries inside components. The only hardcoded per-locale content allowed is navigation (`Utils/MenuItems.tsx`), as documented above.
- If a Prismic-based solution is not possible for a specific case (e.g. deadline, missing credentials), stop and ask before introducing hardcoded content, and record it as technical debt to migrate.
